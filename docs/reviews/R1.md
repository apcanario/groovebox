## Findings

### Errors

**E1. A tab file outside `TAB_FILES` is in no fingerprint, core included.** `tools/smoke_parts.py:249-251` (`part_inputs`): the App closure stops at `src/ui/tabs/`, and tabs are added only through `TAB_FILES` (line 109). A new `src/ui/tabs/X.tsx` imported by `App.tsx` (the way every tab is) and not listed is hashed by no part. Proven on a scratch copy: with `NewTab.tsx` imported by `App.tsx`, all 12 parts report it absent, so a change to it keeps every ledger entry green and the full smoke at close would skip the screen entirely. The comment at line 106 ("core opens every tab, so it has every file") is false in that case. The mechanism must fail closed. Fix: give core every non-test file under `src/ui/` (or every part every `src/ui/tabs/` file that no `TAB_FILES` entry reaches), or make `uncovered()` fail when a file under `src/ui/tabs/` is imported but reached by no `TAB_FILES` entry; add a test in `tools/test_smoke_parts.py` that adds such a file and expects core (at least) to clear.

### Should-fix

**S1. Tab detection misses tabs opened from the Play tab.** `tools/smoke_parts.py:245-247` finds tabs only from a literal `data-tab="..."`, a computed one or `TABS`. `src/ui/tabs/PlayTab.tsx:23` (long-press on a Now tile, `[data-now=...]`) and `:62` (`[data-row=...]` row heads) call `ctx.goTab(id)` and open InstrumentTab, SimpleTab or LayerTab. Today only core uses `hold('[data-now=...]')` (tools/smoke.py:149) and core has every tab, so nothing is wrong yet; the first check in another part that opens a tab this way leaves that tab out of its fingerprint. Fix: when the reached code contains `data-now` or `data-row`, add every instrument and layer tab (drums, bass, synth, layer1, layer2) to `tabs`; add a test.

**S2. `--against` is now misleading.** `tools/smoke_parts.py:10-12` (docstring) and `:301-356` (`against`). It still claims to prove the parts equal a rev's single run, but: on any rev that already has parts, such as the base 367f35d, it crashes with `StopIteration` at line 326 (exit 1 with a traceback); on a pre-parts rev it must report DIFFERENT, since the drop is now `walk_drop` plus six `drop_vibes(..., group)` calls in six browsers; and this shallow clone cannot reach a pre-parts rev at all. Fix: remove `--against`, its docstring lines and `against()`, recording in the changelog that the P10 equality proof was retired by R1's split (it proved the bundle 7 change, and the split is proven instead by `DropGroups`, the 24-tile check and `uncovered()`); or rewrite it to expand drop-1 to drop-6 into the old `walk_drop` plus `drop_vibes(None)` and fail on anything else.

**S3. "The part their change touches" is undefined for engine changes.** `docs/RUN.md:35` and `CLAUDE.md:17`. Any change under `src/` outside `src/ui/` (engine, music, data, styles) clears every part's fingerprint, so read through `--files` the touched parts are all twelve, which is the full smoke the same sentence forbids. P10b (src/engine/drop.ts) is the first row to hit this. Fix: say the part is chosen by what the change does, not by which fingerprints it clears: the part whose checks cover the changed behaviour (for example drop.ts → drop-1, plus the group holding any vibe named in the row), at most two parts, and the full smoke at close catches the rest.

### Minor

**M1. Watchdog interval.** `docs/RUN.md:74` says every 10 minutes in flight and every 15 when idle; R1 says every 10 to 12 minutes. Fix: "every 10 to 12 minutes", or record the 15-minute idle interval as a choice in the changelog.

**M2. No test that a check threshold clears its parts.** `tools/test_smoke_parts.py:108-127` covers function bodies and smoke.py's module code, not a constant of `tools/dropcheck.py`. A later narrowing of `<module>` hashing to "constants the part uses" could drop a threshold silently. Fix: add `self.assertTrue(set(DROPS) <= self.changed("tools/dropcheck.py", "LEVEL_DROP_DB = 3.0", "LEVEL_DROP_DB = 3.5"))` (dropcheck.py:29), and the tests for E1 and S1.

**M3. Functions named in module constants are not followed.** `tools/smoke_parts.py:207` (`_reach`) follows names only inside function bodies. Today the only module constant naming functions is `PARTS` (correctly not followed), so nothing is missed. Fix, to fail closed: when a reached function uses a module constant, also reach the functions that constant names, except `PARTS`.

**M4. Groups 2 to 6 start cold.** `tools/dropcheck.py:421-433`: each group now opens in a fresh browser without `walk_drop` or a previous vibe playing, where the single run measured them after the previous vibe. Not a loosening (the old carry-over of tails is gone, limits unchanged), but this review could run only drop-1. Fix: the main chat's full smoke at close must show drop-2 to drop-6 green; say so in R1's changelog row.

**M5. README says seven parts.** `README.md:100`: "seven resumable parts"; now twelve (drop-1 to drop-6). Fix at close with the README update.

## Verdict
