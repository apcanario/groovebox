## Findings

### Errors

**E1. A vibe's patches and mix change about 0.1 s before the bar line, not on it (spec 7: scheduling on the audio clock; Done-when: lands on the bar).**
`src/engine/index.ts:840-857`. `tick(time)` runs about one lookahead ahead of `time`. `wait = time - ctx.now() - 0.002`: `ctx.now()` is `currentTime + lookAhead`, and Tone's clock only fires ticks with `time <= ctx.now()`, so `wait` is never positive. `applyAll()` therefore runs at once. Every `channel.set` it reaches goes through `ramp()` (`audio.ts:74`), which starts at `currentTime`, about `lookAhead` (0.1 s default) before the bar line. Effect: the last sixteenth of the old song (step 15, already scheduled with the old sound) plays through the new song's filter, drive, levels, sends and envelopes. Mix pump, sweep and saturation also change early. At 122 bpm that is most of a sixteenth, and audible on a filter or level jump. The `ctx.setTimeout` branch is a timer, which spec 7 forbids for scheduling, and it is dead code. The code comment ("exactly here, on the audio clock") is false. The smoke test checks only bpm, section and `landed` after the fact, so it cannot see this.
Fix: add a timed path, `Instrument.applyAt(patch, time)` and `graph.setMixAt(key, v, time)`. Use `rampAt(param, v, time)` (already in `audio.ts:86`) for every continuous value. Hand the wave swap and envelope set to the voice sets with the start time, as `trigger` does, so a new voice is used only from `time`. Call it with the bar's `time` and drop the `ctx.setTimeout`. Add a check to the smoke test: queue a vibe whose synth cutoff differs, then read the native cutoff (as `nativeValue` does for drum levels) 30 ms before and 60 ms after the landing time. It must be the old value before and the new value after.

### Should-fix

**S1. Two quick taps on a vibe arrow start two new songs, and one is never heard but stays in Songs.**
`src/ui/vibes.tsx:120` and `src/store/keeper.ts:114`. `step()` has no busy guard, and `startVibe` is async with awaits (`flush`, `list`, `create`) before `loadAtBar`. A second tap runs while the first is still awaiting. `pendingLoad()` is still null, so `drop` is null, and both create a song. The second `loadAtBar` replaces the first in the engine, but the first song stays in the library. Both taps also read the same `shown`, so a double tap gives "Tropical house" and "Tropical house 2" rather than stepping twice. The picker has `busy`; the arrows do not.
Fix: serialise `startVibe` in `Keeper` (chain each call on the previous call's promise) so the second call sees the first one's pending load and drops it. Compute the next vibe from `engine.pendingLoad()` at call time, not from render state. Add a keeper test: two `startVibe` calls without awaiting the first leave one new song in the library.

**S2. The smoke test's "every instrument audible" can pass with a silent instrument in Ambient.**
`tools/smoke.py:1499` (`solo_bar`) and `:1565`. Soloing gates the other channels, but the shared reverb's tail from the instruments just gated keeps sounding. Ambient's layer 2 reverb is 0.85, with long pad releases, and the threshold is -60 dB. For about a bar after soloing, the master level can stay above -60 dB from the tail alone, so a silent instrument would still pass.
Fix: before each vibe's loop, measure a baseline with every channel gated over the same window, and require each solo to beat it by at least 10 dB. Better still, read a per-instrument level: a `Tone.Meter` on each channel's `level` node, exposed like `level()`.

### Minor

**M1. Patches are data, but nothing lists them.**
`src/music/styles.ts:39` and `src/ui/tabs/SimpleTab.tsx:97`. Spec 8.2 says pickers list whatever exists. Twenty-two patch files exist, yet Simple Synth's "Sound" picker still lists waves, and no Advanced page lists patches. The row's picker bullet names only moods, beats and rhythms, so this is not a P3 Done-when failure.
Fix: carry it to P7 (sounds) as "a Sound picker per instrument listing `PATCH_IDS` for that instrument", and add it to Carried.

**M2. Patch values are not range-checked when the patch files are read.**
`src/music/styles.ts:39`. Only patches a style uses are validated, through `validateSong`. An unused patch file with `cutoff: 5` loads silently.
Fix: in the `readData` check, lay `values` over `defaultPatch` and run the patch checks from `validateSong` (`checkPatch`).

**M3. The vibe control is filled coral when the song has no vibe.**
`src/ui/vibes.tsx:130`. A song from before P3 (no `style`) shows "Pick a vibe" as a filled "on" tile. Spec 8.12 fills a tile only when it is on.
Fix: add `on` only when `vibeName(shown)` is not null; otherwise use the off look (dark tile, 4 px edge).

**M4. Picker tiles do not follow the 8.12 type and state rules.**
`src/style.css:1632-1660`. Vibe names are weight 700; spec 8.12 sets names (vibes) at 800. The off tile has an inset 6 px bar, where 8.12 asks for "a dark tile with a 4 px edge of its colour". The phase2 image only sets the layout, and 8.12 supersedes its look.
Fix: use `font-weight: 800; letter-spacing: -0.02em`, and replace the inner `<i>` bar with a 4 px left edge (`box-shadow: inset 4px 0 0 var(--c)`).

**M5. "Continue last jam" shows the song name where the reference shows the vibe.**
`src/ui/vibes.tsx:95`. `groovebox-6` shows "Deep house · 122". The build shows the song name, which is often "Deep house 2" or user text cut down with an ellipsis.
Fix: show `vibeName(song.style) ?? song.name`, and keep `stripWord` for the fallback.

**M6. The test name claims what it does not test.**
`src/music/styles.test.ts:83`. The name says "Lo-fi and Ambient sit under the old 80 bpm floor", but Lo-fi is exactly 80 and only Ambient is checked.
Fix: rename it to "Ambient sits under the old 80 bpm floor", or check that both are at most 80.

**M7. "Pedal" is a Simple word a non-musician would look up (spec 8.1).**
`src/data/bass/pedal.ts:4`. Simple shows `simple ?? name`, so Ambient's and Lo-fi's bass reads "Pedal".
Fix: add `simple: "One note"` (or "Hold").

**M8. The paging of `PagedChips` has no unit test.**
`src/ui/components.tsx:359`. The paging (opens on the chosen value's page, wraps, pads the last page) sits inline in the component. The smoke test only clicks More until a chip appears.
Fix: move the page arithmetic into `logic.ts` (`chipPage(options, value, per)` returning the page count, the page and the slice) and unit-test it.

## Known issue: 24 tiles at 360 x 640

P3 ships eight tiles, which fit (screenshot), so this is not a P3 failure. It lands in P8. The arithmetic, with every settled rule held:

- 24 tiles in two columns is 12 rows. With 48 px tiles (CLAUDE.md) and 2 px between tiles (8.12): 12 x 48 + 11 x 2 = 598 px.
- "Continue last jam" first is one more 48 px control: one more row and gap, so 648 px. The best case, with no title row, no Close and no note, is 648 px against a 640 px screen. Every layout that keeps all of two columns, one screen, 48 px, 2 px gaps and Continue is 8 px too tall.
- Without Continue (a first launch), 598 px fits and leaves 42 px for a heading that is not a control. Even then, the builder's own CSS will not fit: its title row has a 48 px Close, its row gaps are 10 px, and it has a note line.

No spec-conformant layout exists, so the resolution is a spec change, not a builder's choice. Per RUN section 2, the builder edits `docs/SPEC.md` in the same commit and the changelog says so, and Pedro can veto. The change that breaks the fewest rules:

1. The picker has no title row and no Close: "Continue last jam" is the way back. On a first launch there is no jam, and a tile is the only way in (8.2: tapping a tile loads and plays).
2. Below 648 px of height only, "Continue last jam" takes the first grid cell (half width, 48 px) instead of its own full-width row. Its cell is filled in the vibe's family colour, so it is the 25th cell and reads first. 25 cells is 13 rows: 13 x 48 + 12 x 2 = 648 px, which still does not fit. So the one real concession is either:
   - (a) picker tile rows at 47 px on screens under 648 px tall (11 x 2 + 12 x 47 = 586, plus 48 + 2 for Continue = 636 px), recorded in spec 8.2 as the one exception to the 48 px rule; or
   - (b) the picker's tile gap goes to 1 px on screens under 648 px tall (12 x 48 + 11 x 1 + 1 + 48 = 636 px), recorded in 8.12 as the one exception to the 2 px gap.

   Reviewer's recommendation: (b). A 1 px seam costs nothing to touch or to read, while a sub-48 px target breaks the touch rule that every other screen holds. The note line ("One tap loads...") moves out of the picker, or shows only when the screen is taller than it needs.
3. Smoke `walk_picker_open` must then also assert at 360 x 640 with 24 tiles (use the fixture trick: read the styles folder with 16 fixture files) and with Continue shown, before P8 ships. Without that, the overflow is invisible until the 24th file lands.

Put this in Carried for P8 now, with the arithmetic, so P8's builder does not discover it mid-row.

## Other checks (no finding)

- UI imports no Tone.js. No `Math.random`. Vibe seeds come from an FNV hash of the style id, through `deriveSeed`.
- Bpm 60 to 180 everywhere: `LIMITS`, the bpm drag, validation, the engine setter.
- Held notes of the old song are released on the bar line (`releaseAll(time)`), so there are no stuck notes across a load. A second queued vibe replaces the first. Stop with a vibe queued loads it at once.
- New jam is enabled while playing and opens the picker. Loading while recording is refused, with the reason shown.
- Old saved songs keep their preset ids (tested), and moods stay the same five (tested).

## Verdict

**fix.** One error (E1), two should-fix, eight minor. E1 is a contained engine change (a timed apply path) and does not need a rebuild. The 24-tile picker problem goes to Carried for P8 with the spec change above.
