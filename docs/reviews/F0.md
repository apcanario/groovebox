## Findings

### Errors

**E1. Changing the wave during a note with Sustain at 0 leaves the old sub stuck on a DC level for its whole release. That is a click and a dead sub.** `src/engine/audio.ts:798` and `:829-830`.
Since F0b the sub's pitch is the wave's own frequency signal (`frequency.connect`). Tone's `connectSignal` sets the sub's own frequency to 0 and lets the input drive it. The two old sets still retire on their own, each when its own envelope is under 1e-4. With Sustain at 0 (the dial's range is 0 to 1) the wave's envelope is silent once the decay ends. The sub's envelope never is, because its sustain is at least 0.6 (`subEnv`). So on the next note the old wave's set is retired and disposed while the old sub still sounds. The sub's frequency then drops to 0 Hz, and the sine freezes at whatever phase it was in. Measured here (Minimal techno, Long notes, Sustain 0, Decay 0.1, Release 2, wave changed to triangle mid-note): when the wave set was disposed, the old sub's envelope was at 0.23. 60 ms later the sub's output was a flat -0.147, with no zero crossings. Before, it was a ±0.29 sine. It stays like that until the sub's own release ends, about 1.9 s later. Spec 5 ("every knob is safe to move while playing: no clicks") and spec 7 (ramped, never stepped) are both broken. The old build gave each sub its own pitch, so this did not happen there.
**Fix:** retire the wave's set and its sub as one pair. In `Bass.trigger`, retire both only when both old envelopes are under 1e-4 (one predicate over `monos.old` and `subs.old`, or a `VoiceSets` that holds the pair). Then no set's frequency source is disposed while its sub still sounds. Add a test that fails on HEAD: a `basscheck.py` case, or a smoke check in the part nearest the bass, with Sustain 0, a long release and a wave change in mid-note. It should require that the old sub is never disposed after its wave set, or that the bass scope shows no DC run (no window without zero crossings while the bass sounds).

### Should-fix

**S1. The row's "(tested)" stall test is run by hand only, so nothing guards the fix from here on.** `tools/basscheck.py` (whole file), `tools/smoke_parts.py`.
`check` does not run `stall`, and neither does any smoke part. A later engine change could bring the phase offset back with every script still green. **Fix:** run `basscheck`'s stall measure (0.2 min) as a check inside a smoke part, for example core or drop-5. Register it in `tools/smoke_parts.py` so that part's fingerprint covers `src/engine/bassRun.ts` and `tools/basscheck.py`. Keep the CLI for the before/after proof.

**S2. The FM and noise bass waves are never exercised under the new run model, and the FM branch can break silently.** `src/engine/audio.ts:728-732`.
`runOscillators` finds an FM voice's carrier and modulator through Tone's private `_carrier` and `_modulator`. If Tone ever renames them, it falls back to `[m]`. Then `gateOnly` replaces `FMSynth._triggerEnvelopeAttack` with the carrier's envelope alone: the modulator's envelope never opens and its oscillator never starts. FM bass would lose its FM, and no check would notice. The stall test runs the square only (Rubber), and the levels fixture holds only the nine patches, none of them FM or noise. **Fix:** throw (or count a failure the smoke reads) when the wave is `fm` and either field is missing. Give `stall` a wave argument and run it for `fm` and `noise` as well as the default, in the same smoke check as S1.

**S3. Neither commit records the Done-when evidence the row asks for: drop-5 and drop-6 three times in a row, and the probe's 24 runs.** Fix: at close, run drop-5 and drop-6 three times in a row each (one at a time). Put those six results in the changelog, with the probe (0 of 24 level lines here), the stall (HEAD min +0.871; `059fc3b` down to -0.761) and the levels (worst -0.29 dB). This review ran each drop part once, which does not satisfy "three in a row".

### Minor

**M1. `startTogether` gives up silently.** `src/engine/bassRun.ts:50`. After `RUN_TRIES`, a set whose starts may have reached the audio thread apart is kept, and nothing reports it. **Fix:** count give-ups in an exported stat, as `oscPatchStats.throws` does, and have the smoke require 0.

**M2. Every note now starts at whatever phase the running oscillators hold.** Before, a note after a gap started at phase 0. FM's carrier and modulator now keep one phase relation for the life of the set, which drifts after an FM Ratio move. The sine patches (Sub, 808, Round) may get a different attack thump from note to note. **Fix:** none in code. Name it under Listen for at close, beside the row's "every bass patch must be heard again".

**M3. The bass oscillators run while stopped and while the bass is off,** `src/engine/audio.ts:792` and `:849`: 2 per live set (3 with FM), plus the old set. After Stop, the old set is only retired by a later note. This is a small, constant CPU cost on the phone. **Fix:** in `releaseAll`, after the release, retire the old pair (with E1's joint check), so at most one set runs while idle.

**M4. The probe passes runs with non-level failures.** `tools/basscheck.py:313-320`. A click or stuck-note line from `judge_wind` is printed but does not fail the run. It is within the row's wording ("no level line"), and there were none here. **Fix:** also fail on click and stuck-note lines, or say in the docstring that only level lines count, so a reader does not take a pass as "no clicks".

**M5. One comment line is far over the file's width.** `src/engine/audio.ts:739` (the `subs` doc comment). **Fix:** rewrap it.

## Not found

- No oscillator leak when voice sets are replaced. Disposal waits at least lookahead + 30 ms + 50 ms, which is past a set's start at now + 50 ms. `ToneOscillatorNode.dispose` stops a started node. The retry path's first native nodes get their own stop. drop-5 and drop-6 report 0 oscillator-patch throws.
- Legato: no per-note start remains, so a stalled thread cannot shift the wave and the sub apart. Glide is now scheduled on the wave alone, and the sub follows it at the same audio time.
- No `Math.random()`, no UI import of Tone, no song-format change. `bassRun.ts` is pure and unit-tested (start-together, retry, give-up, strictly increasing starts, envelope-only gating).

## Verdict

**fix.** 1 error, 3 should-fix, 5 minor.
