## Findings

### Errors

- **E1. The MP3 cannot be saved or shared in the APK.** `src/ui/App.tsx:172-181` (save) and `:167-169`, `:185`, `:200` (share). Capacitor 8.6.3 sets no `DownloadListener` on its WebView (none in `node_modules/@capacitor/android/.../getcapacitor/`), so the `<a download>` click on a `blob:` URL does nothing, yet the sheet says "Saved to Downloads.": the take is lost with a message saying it was kept. Android WebView has no Web Share API, so `navigator.canShare` is undefined and Share stays disabled. Both of the take sheet's outputs are dead in the APK (G5's take sheet, C5's listen item can't be done on the APK). OPFS itself (`mp3.worker.ts:23`) should work in a current WebView at `https://localhost`; it is only the hand-off out of the WebView that fails. Minimal fix: one more method on a small native plugin (or `KeepAwakePlugin` renamed `Shell`), called from the take sheet only when `nativeBridge()` is found: JS sends the MP3 bytes (base64, about 2 MB a minute at 160 kbps; fine for a take), Java writes them to `getCacheDir()/takes/<name>.mp3` and either (Save) inserts them into `MediaStore.Downloads` (API 29+, no permission; on API 24-28 write to `getExternalFilesDir(DIRECTORY_MUSIC)` or fall back to share) or (Share) fires `Intent.ACTION_SEND` with a `FileProvider` URI (the provider and a `cache-path` entry are already in the manifest and `file_paths.xml`). The message is set from the plugin's result, not assumed. In the browser the current code stays. Unit-test the JS branch with a fake bridge as `keepAwake.test.ts` does.
- **E2. Updates will not install over the old APK, and the fix INSTALL.md forbids is the one that loses the songs.** `.github/workflows/apk.yml:36-38`, `docs/INSTALL.md:20`. `assembleDebug` signs with `~/.android/debug.keystore`, which AGP creates fresh on every new runner, so each push's APK carries a different signature. Android refuses to install it over the previous one ("App not installed": package conflicts), and the only way past is to uninstall, which deletes IndexedDB (songs). INSTALL.md tells Pedro to install over and not uninstall, which will fail on the second APK. Fix: make one debug keystore once, put it base64 in a repo secret (for example `DEBUG_KEYSTORE_B64`), and before `assembleDebug` add a step `mkdir -p ~/.android && echo "$DEBUG_KEYSTORE_B64" | base64 -d > ~/.android/debug.keystore` (or a `signingConfigs.debug` in `app/build.gradle` reading a path from the environment). Do not commit the keystore (`android/.gitignore` ignores `*.keystore`, keep it so). Add a line to INSTALL.md only if the first APK built before this fix must be uninstalled once. `tools/release_check.py` can check the step exists.

### Should-fix

- **S1. Orientation is set once, in `onCreate`.** `android/app/src/main/java/com/apcanario/groovebox/MainActivity.java:19-24`. The manifest (`AndroidManifest.xml:13`) lists `smallestScreenSize|screenSize|screenLayout`, correctly, so rotation and fold changes do not recreate the activity and audio survives; but then nothing re-reads `smallestScreenWidthDp` when it changes (a foldable opened or closed, a display-size change, a tablet put into split screen), so a folded phone opened to its inner screen stays portrait-locked and an unfolded tablet folded keeps rotating. Fix: override `onConfigurationChanged(Configuration c)`, call `super`, then `setRequestedOrientation(OrientationRule.requestedOrientation(c.smallestScreenWidthDp))`. (Targeting API 36, Android 16 ignores orientation locks at 600 dp and up anyway, so the tablet side is safe there; the phone side needs this.)
- **S2. The AudioContext keeps running in the background.** `src/ui/background.ts:38-41`. Stop silences the engine, but with `KeepRunning` true the WebView and its audio thread run on behind the lock screen, rendering silence: a battery cost for no sound, and on some phones a media session shows. Spec 2 is met (no audio), but the cost is real on long breaks. Fix: after Stop, once the take tail is done (`recordInfo().state === "off"`), suspend the context through an engine method (`engine.sleep()` in `src/engine/`, not Tone from the UI), and resume on the next Play (Play's tap already resumes the context on a first tap). Test with the fake transport in `background.test.ts`.
- **S3. No versionCode bump.** `android/app/build.gradle:10`. Every APK is versionCode 1 / "1.0", so the installer shows no update and Pedro cannot tell which build is on the phone. Fix: `versionCode (System.getenv("GITHUB_RUN_NUMBER") ?: "1") as Integer` and a versionName carrying the short SHA; show nothing new in the app.

### Minor

- **M1.** `apk.yml:15` with `:49-50`: `cancel-in-progress: true` can cancel a run between `gh release delete` and `gh release create`, leaving no release until the next run finishes. Fix: build first (as now), then use `gh release upload latest groovebox-debug.apk --clobber` plus a `git push -f origin HEAD:refs/tags/latest` to move the tag, creating the release only when `gh release view latest` fails; or set `cancel-in-progress: false`.
- **M2.** `android/app/src/main/AndroidManifest.xml:40`: `INTERNET` is not needed: Capacitor's `WebViewLocalServer` serves `https://localhost` from assets through request interception, and the app loads nothing from the network (offline check clean). Keeping it is harmless; dropping it makes "works offline" a fact of the manifest. Either way, say which in the changelog.
- **M3.** `android/app/src/main/res/xml/file_paths.xml:3`: the template's `external-path path="."` shares the whole external storage root through the provider; unused today. If E1's fix uses the provider, keep only `<cache-path name="takes" path="takes/" />`.
- **M4.** `docs/INSTALL.md:24`: songs made on the Pages site live in the `apcanario.github.io` origin and do not appear in the APK (`https://localhost`), and the other way round. Say so in one line.
- **M5.** `src/ui/App.tsx:116`, `:140`: the native keep-awake calls in `useWakeLock` (set on mount with `false`, release in cleanup) have no test; the behaviour is right by reading (the `on=false` effect run also sends `false`, and FLAG_KEEP_SCREEN_ON dies with the window, so no leak when the app stops or is killed). A small test with a fake bridge would pin it.
- **M6.** `MainActivity.java:24`: a phone launched while held sideways first draws in landscape (activity not recreated), then turns to portrait: one frame of the phone layout at landscape size. Cosmetic; `android:screenOrientation="portrait"` cannot be used because tablets must rotate, so leave it unless seen.

## Checked and fine

- Spec 2: no `<service>`, no `FOREGROUND_SERVICE`, `WAKE_LOCK` or audio permission in the manifest; `release_check.py` guards it. `stopInBackground` stops on Capacitor's `pause` document event (`Bridge.onPause` → `MockCordovaWebViewImpl.handlePause` → `triggerDocumentEvent("pause")`, fired whatever `KeepRunning` is) or on hidden, whichever first, and only while `running`; nothing restarts on return. Spurious stops: rotation is handled by `configChanges`, so no onPause; the app asks for no runtime permission; the take sheet only opens after Stop, so a share sheet or file picker (once E1 is fixed) pauses an engine that is already stopped; in the browser it adds no listener. A take in progress ends as Stop ends it (tail, then the sheet) and the test proves it with the real Engine.
- Keep awake: `FLAG_KEEP_SCREEN_ON`, no permission, set on Play and cleared on Stop through `useWakeLock`; calls are serialised on the UI thread.
- Offline: dist loads nothing from the network (the URLs in the bundle are licence and namespace strings); fonts bundled; no service worker; base `./` resolves under `https://localhost`; IndexedDB and OPFS are origin storage of the WebView.
- Icon: adaptive foreground, monochrome (Android 13 themed icons) and background colour, plus legacy square and round PNGs at all five densities, drawn by `tools/make_icon.py` from a fixed note list (original artwork, lanes inside the 66 dp safe circle); the template's Capacitor artwork is gone.
- Orientation rule: under 600 dp portrait, 600 dp and up `FULL_USER`, unit-tested in JUnit and run in the workflow. Controls under 48 px: not applicable (no new UI).
- Repo hygiene: no keystore, `local.properties`, `.env` or `.watchdog` committed; `.gitignore` keeps `.watchdog`, `android/.gitignore` keeps `*.jks`, `*.keystore`, `local.properties` and the generated assets out.
- Capacitor packages are devDependencies and nothing in `src/` imports them; the notes give the changelog line CLAUDE.md asks for. BACKLOG, CHANGELOG and README updates are the main chat's at close.
