## Findings

### Errors

None.

### Should-fix

**S1. The pad filter changes a lookahead before the bar line, and a releasing pad tail is heard through the open filter.** `src/engine/index.ts:450` calls `useMode` from `tick(time)`, and `src/engine/audio.ts:605-606` ramps the pad filter and motion depth with `ramp()`, which starts at `Tone.getContext().currentTime`, not at `time`. So on a Pad to Arp/Generative mode switch, or a section switch from a section with the layer in Pad to one without, the filter jumps from the brightness point (for example 1.2 kHz at the default 0.4) to 10 kHz about one lookahead before the bar line, while the old pad chord is still holding, and its whole release (up to 8 s) then plays at 10 kHz. That is a sudden brightness jump on the held chord before the switch lands, against section 3 (switches land on the bar line) and section 7 (scheduled ahead on the audio clock). The reverse direction closes the filter on the last arp notes early. Fix: give `useMode` the step's `time` and schedule the filter and depth changes from it (`cancelAndHoldAtTime(time)` then `setTargetAtTime(value, time, …)`); when leaving Pad mode, open the filter over the pad's release (for example a time constant of `min(release, 1) / 3`) instead of 30 ms, so the tail fades out at its own brightness. Knob moves within Pad mode can keep acting at once. Add a smoke check: switch Pad to Arp just after a bar line and read `padHz` before the bar line; it must still be at the brightness value.

### Minor

**M1. New seed mid-bar starts the loop mid-bar for good.** `src/engine/sequencer.ts:539-543` with `src/music/lead.ts:111`. When `newSeed` changes the seed while playing, the next step builds a fresh `GenerativeLead` with `counter = 0` at whatever step the bar is on; slot 0 then lands on that step in every later bar (with length 16 the melody stays rotated against the bar), and `barStart` stays 0 until the next bar, so `preview` shows the wrong slots for the rest of that bar. Fix: when the sequencer replaces a lead, set its counter to the current bar step (add a `start(barStep)` or constructor argument), and set `barStart` accordingly; add a test that a new seed at step 6 gives a loop aligned to the bar from the next bar.

**M2. The lead row flips to the next bar a lookahead early.** `src/music/lead.ts:111` sets `barStart` when the sequencer computes step 0, which is ahead of what the UI shows as `pos.step` (`LayerTab.tsx:37-44`). For the last lookahead of each bar the row shows the next bar's hits with the old bar's playing step. Fix: keep the previous bar's view until the UI's step wraps (store `prevBarStart` and pick by `pos.step`), or have the engine report the view per audio-clock bar.

**M3. Mode and layer levels differ a lot.** Smoke: layer 1 pad -14.3 dB against generative -25.8 and arp -27.8; layer 2 sits 10 to 16 dB under layer 1 in generative and arp at the same knob settings. A mode switch jumps the level by about 12 dB. Fix: not a code rule; add it to Carried as a listen item for Pedro (pad loudness against arp and lead, layer 2 against layer 1), and if he hears it, add a per-mode trim in `Poly` (`src/engine/audio.ts`).

**M4. The in-key test covers Layer 1 only.** `src/engine/g4.test.ts:38-58`. Layer 2 runs the same code but has its own arp RNG and lead keys. Fix: loop over `LAYER_IDS` in `layerSong` and the assertions.

**M5. Pad dials reuse an attack knob spec for brightness and motion.** `src/ui/tabs/LayerTab.tsx:132` and `src/ui/logic.test.ts` (pad test) build `{ key: "attack" as const, … }` for every pad dial so `knobPos` and `knobText` type-check. It works (no `seconds` means linear), but the key is false. Fix: give `knobPos`, `knobValue` and `knobText` a spec type that needs only `label` and `seconds`, and pass `PAD_KNOBS` entries directly.

**M6. Smoke does not check that a mode switch lets go of the pad.** `tools/smoke.py` `walk_g4`. It checks sound per mode but not that held pad voices release when the mode changes, as it does for the synth's Held to Stabs. Fix: expose the layer's active voice count (as for the synth), switch Pad to Arp, and require the pad voices to drop within the pad release plus a bar.

## Verdict

**fix.** 0 errors, 1 should-fix, 6 minor. Every Done-when item is true and both scripts pass; S1 is a timing and brightness jump on Pad mode changes that the fixer should schedule on the audio clock.
