# G6 slice b: notes for the main chat

- **Background stop (spec section 2), choice:** web side only, `src/ui/background.ts`, wired in `App.tsx`. Capacitor 8.6.3 never pauses the WebView (Bridge `KeepRunning` defaults to true), but on every activity onPause its `MockCordovaWebViewImpl.handlePause` fires a `pause` document event through `window.Capacitor.triggerEvent`. Inside the shell the app calls the engine's own Stop on that event or on `visibilitychange` to hidden, whichever comes first (Stop only if running). A take in progress ends as Stop ends it: 1.5 s tail, then the take sheet. Nothing restarts on return. No native change: MainActivity is untouched. In a browser (Pages) nothing changes, so the smoke runs as before. The AudioContext is not suspended (it goes silent with Stop; suspending would cut the take's tail). Test: `src/ui/background.test.ts` (real Engine with Tone faked).
- **Workflow:** `.github/workflows/apk.yml`, push to main and workflow_dispatch, own concurrency group `apk`. Java 21, not 17: Capacitor 8's Android library compiles for `JavaVersion.VERSION_21`, so 17 cannot build it. `android-actions/setup-android@v3`, `npm ci`, `npm run build:android`, `./gradlew assembleDebug`, `./gradlew testDebugUnitTest`, then `gh release delete latest --cleanup-tag` and `gh release create latest groovebox-debug.apk --prerelease --target $GITHUB_SHA` (recreated each push so the tag follows the commit). `pages.yml` is untouched.
- **Checks:** `tools/release_check.py` (with `tools/test_release_check.py`, now in `npm run check`) fails if apk.yml lacks the push-to-main trigger, assembleDebug, testDebugUnitTest, release `latest` (prerelease, asset groovebox-debug.apk) or `contents: write`; if pages.yml stops building with `npm run build` and deploying dist, or shares apk.yml's concurrency group; if vite's base is no longer `./`; if the manifest asks for a foreground service, wake lock or audio permission or declares a `<service>`.
- **Not run here:** `./gradlew assembleDebug` and `testDebugUnitTest` (no Android SDK in this container), the workflow itself, and actionlint (not installable here; the YAML is parsed by PyYAML instead). The first push to main is the workflow's first run.
- **Pages build:** `npm ci && npm run build` at f09a02f and at this slice give the same six files (index.html identical but for hashes; main JS 704.24 kB to 705.07 kB).
- **Docs:** `docs/INSTALL.md`.

# G6 review fixes: notes for the main chat

- **E2, signing (choice):** one debug keystore made with keytool (PKCS12, alias `androiddebugkey`, store and key password `android`, RSA 2048, 10000 days, `CN=Android Debug,O=Android,C=US`; SHA-256 FC:7B:58:72:...:F4:40) is committed as `android/app/debug.keystore` and is the debug `signingConfig` in `android/app/build.gradle`. No repo secret (no agent can create one). It is Android's standard public debug key, not a secret, and must never sign a Play release: there is no release signing config, and `tools/release_check.py` fails on one, on a release build type with a `signingConfig`, on a debug build not signed with this file, on this file missing, and on any other `*.keystore`/`*.jks` in the repo. `android/.gitignore` still ignores `*.keystore` and `*.jks` and un-ignores only `app/debug.keystore`. An APK built before this has another signature: uninstall it once (INSTALL.md says so).
- **E1, save and share in the APK:** `TakePlugin` (`android/.../TakePlugin.java`, Capacitor plugin `Take`, registered in MainActivity) with `write`, `save`, `share`; the web side is `src/ui/takeOut.ts`, used by the take sheet only when `window.Capacitor` has the `Take` plugin; the browser path is unchanged. The MP3 crosses the bridge in base64 chunks of 384 KiB (about 512 kB of text per message; a ten-minute take of about 11 MB is about 30 messages), appended in order to `cacheDir/takes/<name>` (an out-of-order chunk is refused; save and share check the byte count). Save inserts into `MediaStore.Downloads` (API 29+, no permission). API 24 to 28: no permission is added (a public Downloads write there needs WRITE_EXTERNAL_STORAGE), so save answers `old-android` and the sheet says to use Share, which works on every version. Share is `ACTION_SEND` with a FileProvider URI; `file_paths.xml` now shares only `cache/takes/` (M3). The message is the plugin's answer: "Saved to Downloads." only on `saved: true`. Tests: `src/ui/takeOut.test.ts`; `TakeName` (file-name cleaning) has a JUnit test, run here with javac and JUnit 4.13.2 by hand.
- **S1:** `MainActivity.onConfigurationChanged` re-applies the phone/tablet orientation rule.
- **S2:** `Engine.sleep()` / `Engine.wake()` (`src/engine/index.ts`): suspend the raw AudioContext only when stopped and no take is recording or closing; resume on return and at the start of `play()`. `background.ts` calls sleep after its Stop (waiting on `onChange` for a take's tail to close) and wake on Capacitor's `resume` event or the page turning visible. Browser: never called (play's wake does nothing to a running context). Tests in `src/ui/background.test.ts`.
- **S3:** versionCode = `GITHUB_RUN_NUMBER` (1 locally), versionName = package.json's version plus `+<run>` (or `+local`). The review's short-SHA name was replaced by the run number, which is what the release notes and the Actions page show.
- **M1:** `apk.yml` concurrency `cancel-in-progress: false` (release_check fails on true).
- **M2, INTERNET kept:** the Capacitor template keeps it, and whether its WebView loads `https://localhost` through request interception without the permission could not be tried on a device here; a wrong guess is a blank app. The offline check still proves dist loads nothing from the network.
- **M4:** INSTALL.md says web and APK songs are separate. **M5:** the native side of `useWakeLock` is now `holdNativeKeepAwake` in `keepAwake.ts`, tested. **M6:** left, as the review says, unless seen.
